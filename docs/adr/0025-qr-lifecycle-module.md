# Capture QR writes via QR lifecycle module

Capture **QR code** writes (Create digital guest link, Update internal description, Pause/Resume, Rotate, Archive, Restore) and **Pause / Activate location capture** live in one **QR lifecycle module** with typed domain results. Controllers stay thin HTTP adapters: Owned-location authz remains in the action; business outcomes map to status codes. Existing mutation routes and request/response shapes stay frozen — backend deepen only. We keep **Capture Archive** list composition on ADR-0024 / the **Capture Archive list module** (including any interim archived GET body), not inside lifecycle. We rejected splitting per-code vs location capture into two public modules (restore-set and location-Paused lock are one story), returning `IActionResult` from the domain seam, and reshaping HTTP or frontend adapters in this cut.
