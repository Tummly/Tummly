# Multi Capture Preview via Capture preview-options + clear-on-close

Multi-location Capture root guest-experience Preview loads **Capture preview-options** (`GET /api/capture/locations/{locationId}/preview-options`) — Active/Paused **QR code** label facts only — instead of full placements or **Capture location snapshot** metrics. A **Capture preview-options module** owns authz, Active/Paused filtering, and label projection; the HTTP action stays a thin adapter. The **Operator Multi Capture page module** replaces its placements adapter with a preview-options adapter and clears preview Maps when the picker or overlay closes (refetch on next Preview). Per-location Capture Preview keeps using in-memory body facts from the snapshot/body load. We rejected permanent snapshot over-fetch for Multi Preview (ADR-0022’s interim), lean-mode flags on the snapshot route, Active-only picker lists, and LRU caches. QR lifecycle extraction and shared frontend preview submodules stay separate seams.
