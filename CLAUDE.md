## Verify setup

Run facts for `/verify` (`.claude/skills/verify/SKILL.md`).

- **Dev:** `npm run dev -- --port 5173 --strictPort` → http://localhost:5173. Playwright's `webServer` starts the same command and reuses a running server. Probe the port first and run one Vite per checkout: a second start rewrites `node_modules/.vite` and the running server then serves `504 (Outdated Optimize Dep)` and a blank page (cure: restart that server).
- **API:** the dev app calls the local API at `http://localhost:5204/api` (`.env.development.local` wins over the QA URL in `.env.development`). Start it with `./scripts/run-local-api.sh` (needs the `tummly-mssql` Docker container); wait for `curl http://localhost:5204/health/ready` → `{"status":"ready"}`. A blank page with `ERR_CONNECTION_REFUSED` on `:5204` means the API is down. Weekly brief `Azure OpenAI … 404` lines in its log are background-job noise.
- **Seed:** the API seeds the catalogs and the Development Admin/Support logins on start. Copy QA data into local SQL with `./scripts/sync-qa-db-to-local.sh`. Demo guests and feedback for one Pilot owner: `./scripts/seed-qa-pilot-demo.sh --email <owner>` with `CONNECTION_STRING` set to the local DB (its default target is QA). Other test data: create it through the UI flow under test.
- **Login:** sign in with `signIn(page, "operator" | "admin" | "support")` from `e2e/auth.ts`; `e2e/sign-in.spec.ts` proves each role lands on its dashboard (`/single-dashboard`, `/admin-dashboard/admin`, `/admin-dashboard/support`). Values live in the gitignored root `.env` (`E2E_OPERATOR_*`, `E2E_ADMIN_*`, `E2E_SUPPORT_*`), which `playwright.config.ts` loads; keep them out of tests and commits. In MCP browser flows, set `localStorage.deviceToken` to `E2E_OPERATOR_DEVICE_TOKEN` before the operator signs in: that registered Trusted device skips the Sign-in OTP email, which no agent can read (the DB keeps only its hash).
  - The logins exist only in the local DB: operator = `Users.Id = 3` renamed to `e2e.operator@tummly.test` (Owner, single location, Active Growth plan, Trusted device until 2036); Admin and Support = `Admins` rows `E2E Admin`, `E2E Support`. `.scratch/verify-setup/restore-local-db.sql` undoes all three. `sync-qa-db-to-local.sh` replaces the DB and removes them; recreate them with new passwords and a new device token.
  - A sign-in that fails → check the rows with `sqlcmd` in `tummly-mssql` before blaming the UI.
- **Browser:** MCP flows run in the T3 Code browser, not a separate Chromium. T3 starts with `--remote-debugging-port=9222` through `~/.local/bin/t3code-cdp` (newest AppImage; the launcher `~/.local/share/applications/com.t3tools.T3Code.desktop` calls it). A T3 self-update relaunches without the switch, so start T3 again with `t3code-cdp` after each update. Then the `chrome-devtools` server attaches to `http://127.0.0.1:9222`. Check `curl -s http://127.0.0.1:9222/json/version` first; no answer → T3 runs without the switch, so ask the user to quit T3 and run `t3code-cdp`.
  - Open the page with T3 `preview_open` (the user sees it in the browser panel), then in Chrome DevTools MCP `list_pages` → `select_page` the entry with that URL. T3 tabs are `webview` targets; `--experimentalIncludeAllPages` makes them visible. Drive the flow with Chrome DevTools MCP (`take_snapshot`, `click`, `fill`, `evaluate_script`, `take_screenshot`, console and network lists, `emulate` for slow or offline network). Resize with `preview_resize`.
  - The target list also holds T3's own app window (`t3code://app/…`). Act only on the `localhost:5173` tab: an action on the app window changes T3 Code itself.
  - No Playwright MCP: Playwright over CDP sees only the T3 app window, never the webview tab. Playwright is the test runner only; `npx playwright test` runs its own headless Chromium, so saved tests stay isolated from the T3 session. Stub error and loading states with `page.route` in the saved test.
- **Breakpoints:** 375, 768, 1024, 1440. 1024 is Tailwind `lg`, the main layout switch in `src/`.
- **Spec:** `.scratch/<feature-slug>/PRD.md` and its tickets `.scratch/<feature-slug>/issues/*.md` (UI tickets carry Figma URLs under `## Figma`); older PRDs in `docs/prds/`. Code wins over a stale spec.
